# MAGMA Integration Plan for Court of Core Memory

## 1. Alignment Summary

| Court of Core Memory (8 dimensions + governance) | MAGMA (4 orthogonal graphs + policy traversal) | Notes: Synergies + Potential Conflicts |
|---|---|---|
| **Dimensions: Entity** (named instances; "Who") | **Entity graph** (links events to abstract entity nodes; "object permanence" across timeline segments) | **Synergy:** Direct conceptual alignment. Court's strict orthogonality rule ("named instances only") can *tighten* MAGMA's entity extraction discipline. **Potential conflict:** MAGMA's entity nodes are "abstract entity nodes" and may blur Court's Entity vs Semantic separation unless constrained. |
| **Dimensions: Semantic** (concepts/topics; "What") | **Semantic graph** (undirected similarity edges; also vector DB for embeddings) | **Synergy:** Both separate semantic similarity from other relations. Court's explicit "Semantic dimension != Entity" rule addresses a common failure mode of semantic-only retrieval. **Potential conflict:** MAGMA's semantic edges are defined by cosine thresholding, which can re-introduce "flattening" if over-relied upon; Court expects multi-dimensional structure to remain first-class, not be dominated by the semantic layer. |
| **Dimensions: Temporal** (bi-temporal validity windows; "When"; staleness handled via temporal modeling) | **Temporal graph** (immutable ordered backbone; strict ordering by timestamps; temporal parsing to absolute window) | **Synergy:** Strong alignment on temporal grounding as a primary structure. **Potential conflict:** Court's temporal modeling is *also* about validity windows / supersession semantics; MAGMA's temporal backbone is primarily chronological ordering. Court's stronger governance around "state facts changing over time" could be missing in MAGMA. |
| **Dimensions: Causal** (backward-observed cause only; "Why"; forward goes elsewhere) | **Causal graph** (directed "logical entailment" edges inferred during consolidation; supports "Why" queries) | **Synergy:** Both treat causality as a distinct relation type used for "Why" reasoning. **Potential conflict:** Court enforces a *directional semantic constraint* (backward-only) and separates forward-looking consequences into **Implication**; MAGMA does not introduce a separate implication/forward-consequence graph, so causal edges may be asked to serve both roles. |
| **Dimensions: Spatial** ("Where"; scope/container: file path, conversation ID, workspace, process, context-window slice) | Not a first-class graph (MAGMA focuses on semantic/temporal/causal/entity) | **Synergy:** Court can extend MAGMA-like multi-graph retrieval into operational "where" contexts (codebase scope, run context). **Potential conflict:** MAGMA-style retrieval may underperform on "where" queries unless augmented; Court treats this as a core orthogonal dimension, MAGMA does not. |
| **Dimensions: Procedural** (steps/sequence; "How"; steps vs dependencies separated) | Not a dedicated graph (procedural info may live in event text / semantic similarity) | **Synergy:** Court's Procedural dimension fills a gap: "how-to" retrieval becomes structured traversal rather than semantic recall. **Potential conflict:** MAGMA's design might conflate procedural sequences with temporal adjacency; Court distinguishes "sequence-of-steps" from "happened-after." |
| **Dimensions: Implication** (forward outcomes / lessons; "what it means"; forward-only) | Not a dedicated graph (may be synthesized during narrative context construction) | **Synergy:** Court provides a *place to store* forward insights as first-class retrievable structure (not just generated at query time). **Potential conflict:** MAGMA's retrieval/synthesis pipeline may treat implications as an output artifact; Court expects implications to be governable facts that can be certified/contested. |
| **Dimensions: Resources** (external dependencies invoked; "what aided"; separated from steps) | Not a dedicated graph (tools/resources may be attributes) | **Synergy:** Court's Resources dimension maps well to tool-using agents and supports auditability ("which tool/library/system produced this"). **Potential conflict:** MAGMA's generic "attributes" may not provide the strict separation Court wants between "procedure steps" vs "resources invoked." |
| **Validation Court (governance):** formal state machine; Court is sole transition authority; deterministic rule engine with narrow auditable LLM subroutines; Stage 0 immutable evidence anchoring; states like Certified/Contested/Conflicted/Superseded/Archived/Deprecated; mandatory Observed-Internal logs for every LLM subcall | **Retrieval logic:** intent-aware router classifies query intent (e.g., Why/When/Entity), chooses traversal policy weights, anchors via multi-signal fusion (dense + lexical + temporal), then heuristic beam search with transition scores combining semantic similarity + edge-type weights; linearizes retrieved subgraph with provenance tokens (`<t:...> ... <ref:...>`) and salience budgeting | **Synergy:** Both prioritize interpretability (paths, provenance) and structured retrieval beyond pure embeddings. Court's governance + Stage 0 anchoring can strengthen MAGMA's hallucination mitigation (Court makes "truth admission" explicit). **Potential conflict:** MAGMA's core selection is *policy-guided retrieval*; Court's core differentiator is *truth governance and lifecycle*. MAGMA can retrieve "memories" without an explicit certification regime; Court would treat that as epistemically unsafe unless restricted to Stage 0 (evidence) or certified core nodes. |
| **Write/update pipeline:** Court loop is event-driven via nominations; strict separation Stage 0 -> Court -> Persistent Core; Reflection proposes, Court certifies; explicit human review option for contested/conflicted | **Dual-stream ingestion:** Fast path "synaptic ingestion" (segment, index, update temporal backbone) vs slow path "asynchronous consolidation" (LLM infers causal/entity links) | **Synergy:** Very compatible in spirit: both decouple latency-sensitive logging from slower structuring. Court can map cleanly onto: fast path ~= Stage 0 append; slow path ~= Reflection+Court nomination/certification cycles. **Potential conflict:** MAGMA's slow-path LLM adds edges as part of consolidation; Court requires that *state transitions and certifications* be rule-governed and logged, and (in Court's design) LLM is never allowed to assert validity beyond mechanical allowances. |

## 2. Architectural Decisions

- **Court remains the sole gatekeeper.** MAGMA-style components are limited to retrieval support, segmentation, indexing, candidate edge proposal, and query-planning assistance. They do not certify facts, change node states, assign Validation Basis, or write directly into the Persistent Core. Any extracted node, inferred edge, abstraction, or contradiction judgment still enters through the existing Stage 0 -> nomination -> Court pipeline. This preserves the locked principle that all state transitions are Court-mediated.
- **MAGMA-style graphs map onto Court's eight orthogonal projections as a constrained subset, not a replacement.** Entity maps to Entity; Semantic maps to Semantic; Temporal maps to Temporal, but Court retains separate bi-temporal validity and supersession semantics; Causal maps to Causal, but only for backward-observed causes. Spatial, Procedural, Implication, and Resources remain Court-native first-class projections and must not be collapsed into generic semantic metadata just because MAGMA does not model them explicitly.
- **Dual-stream ingestion should terminate at Stage 0, not bypass Court.** The fast path appends raw observations, segment metadata, timestamps, and retrieval indexes to Stage 0 or Stage-0-adjacent auxiliary indexes for low-latency recall. The slow path performs asynchronous consolidation over Stage 0 material and existing Certified nodes to propose entity links, temporal links, causal links, abstractions, or synthesis candidates. Those outputs remain proposals until Court review. Fast path improves recall latency; slow path improves structure; neither path is allowed to mint truth directly.
- **The Intent-Aware Router belongs inside Retrieval policy, downstream of query formation and upstream of traversal.** It should sit after Working Memory Current contents seed the retrieval query, but before multi-layer traversal weights and beam expansion are applied. Its role is to classify intent such as Who/What/When/Where/Why/How/Implication/Resources, choose a retrieval policy profile, and emit a traceable weighting plan. It does not overrule Court-imposed state penalties, evidence constraints, or certification boundaries.
- **Certified facts and uncertified evidence must remain visibly distinct at retrieval time.** Retrieval may draw from both Stage 0 evidence and Persistent Core nodes, but the returned package must preserve provenance labels so the agent can distinguish raw evidence, Court-certified facts, Contested material, and inferred proposals. MAGMA-style provenance tokens are useful here, but they should carry Court-native epistemic labels rather than a single undifferentiated memory status.
- **Graph materialization should stay conceptual in v1.1 documentation.** The current repo explicitly defers a concrete persisted representation of the eight projection graphs. Therefore the integration plan should specify traversal semantics, policy profiles, and data contracts first, while leaving physical storage, indexing backend, and graph engine choice for a later implementation revision.

## 3. Open Questions & Resolutions

- **Ambiguity: Does MAGMA become the new memory substrate?** Resolution: No. Court's Persistent Core remains the authoritative memory substrate. MAGMA contributes retrieval and graph-traversal patterns that operate over Court-governed data and Stage 0 evidence.
- **Ambiguity: Can slow-path consolidation write inferred edges directly for performance?** Resolution: No. Slow-path outputs may be stored only as auxiliary retrieval hints or as nominations awaiting Court review. Any edge that carries epistemic meaning inside the Persistent Core must be Court-certified.
- **Ambiguity: How should MAGMA's four graphs coexist with Court's eight projections when storage is still design-only?** Resolution: Treat MAGMA as a conceptual retrieval overlay and crosswalk. In v1.1 docs, define mapping and traversal rules without committing to a concrete graph database representation.
- **Ambiguity: Should the router be a Court subroutine?** Resolution: No. The router belongs to Retrieval, not Court. Court subroutines remain narrow and auditable around validation tasks, while routing is a query-planning concern with trace output rather than a state-transition authority.
- **Ambiguity: Where do forward consequences inferred by MAGMA-style reasoning go?** Resolution: Into Court's Implication projection, never back into Causal. This keeps Court's backward-only causal rule intact.
- **Ambiguity: How should procedural sequences and resource usage be handled if MAGMA lacks dedicated graphs for them?** Resolution: Keep both as explicit Court-native dimensions. Retrieval policy may emulate MAGMA's multi-graph weighting, but it must include Procedural and Resources as separate scoring channels rather than folding them into temporal or semantic similarity.
- **Ambiguity: Can Stage 0 segment indexes influence retrieval before Court certification?** Resolution: Yes, but only as evidence retrieval aids. They may help surface raw observations quickly, yet they do not upgrade those observations into certified memory and must be labeled as Stage 0 evidence in results.
- **Ambiguity: Does temporal backbone ordering replace Court's bi-temporal validity model?** Resolution: No. Chronological ordering is additive, not substitutive. Court keeps effective-time and supersession semantics as the authoritative model for changing state facts.

## 4. Prompt Template Updates Needed

- **`node-kind-proposal`** should accept segmented Stage 0 excerpts without changing its authority boundary. If nominations begin coming from MAGMA-style consolidation, the prompt should include concise provenance fields such as source segment IDs and whether the proposal originated from raw evidence or a consolidation pass, while still producing only a Node Kind classification.
- **`conflict-likelihood`** should be extended to receive dimension-aware context summaries rather than plain text alone. Useful additions are overlapping entity IDs, temporal overlap status, and the candidate relation type so the scorer can distinguish direct contradiction from likely supersession or harmless parallel facts.
- **Global constraints in `PROMPT_TEMPLATES.md`** should add a rule that graph snippets, traversal paths, and provenance tokens are admissible prompt inputs, but no prompt may treat them as self-authenticating evidence. Stage 0 anchors and Court-certified nodes remain the only admissible grounding bases.
- **The implied `evidence-justification` prompt family** should be documented explicitly to match the existing verifier and wrapper references. Its template should require citation only to Stage 0 anchors, Certified node IDs, and Court-assigned Validation Basis values, never to free-floating MAGMA inference output.
- **Prompt verification guidance** should clarify that retrieval-layer prompts, if later introduced for routing or subgraph linearization, live outside Court's state-transition authority and therefore must not be allowed to mutate memory state. They still need trace logging, but not Court certification semantics.

## 5. Phase 1 Scope for v1.1

- Document the MAGMA-to-Court alignment and make explicit that MAGMA is integrated as a retrieval and structuring pattern, not as a competing governance model.
- Document the crosswalk from MAGMA's four graph families to Court's eight orthogonal projections, including the rule that Spatial, Procedural, Implication, and Resources remain first-class Court dimensions.
- Document a dual-stream ingestion model where the fast path supports Stage 0 segmentation and indexing, while the slow path produces Court-bound proposals only.
- Document the Intent-Aware Router as a Retrieval-layer component that selects policy weights and emits retrieval traces without bypassing Court controls.
- Document provenance rules for mixing Stage 0 evidence, Certified nodes, Contested or Conflicted nodes, and inferred proposals in retrieval output.
- Defer implementation details such as persisted graph storage, new retrieval services, new state types, distributed Court designs, benchmark claims, and any direct-write MAGMA consolidation path.
